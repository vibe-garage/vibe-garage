A game you can only lose is a treadmill with a death screen. This episode gives the run a finish line: a final wave — wave ten — and a victory screen that proves the ending with numbers the game actually counted. The win is built the way this series builds everything: as an event, not a poll. The first version checked “how many crabs are left?” every frame, and declared victory on the opening frame, because the count reads zero before wave one. The shipped version shouts the win from inside the wave-cleared check, the one moment it is actually true. Moments are events, never polls.

What you build

  1. Build the screen by mirroring a screen you trust: a second CanvasLayer named Victory beside Episode 7’s GameOver — Process Mode Always, a hidden full-rect Panel, a gold YOU WIN title, four stat labels left as placeholders, and a Hint label that reuses Episode 7’s restart action.
  2. Write the listener: victory.gd hides the panel in _ready, finds the spawner by its group, and connects its run_won signal to one function. That function guards itself with a flag (the win shows exactly once), fills the four labels from the stats it was handed, shows the panel, and pauses the tree. Its restart unpauses first, then reloads — Episode 7’s order.
  3. Give the run an end: the spawner gains a final_wave setting (10). Inside the wave-cleared check — the event, not a loop — clearing the final wave shouts run_won with a dictionary of the run’s numbers; any other wave starts the break timer exactly as before. A guard flag means the shout can never happen twice.
  4. Count only at events: crabs_zapped increments in the died hookup and gems_collected in the gem hookup, beside the score. Nothing is polled, nothing is derived. Note who is NOT counted: the boss never emits the crabs’ died signal (Episode 12’s rule), and its minions die through a separate hookup that rolls their loot but never touches the tally — so a winning run’s counter reads exactly the waves’ crabs.
  5. Settle the photo-finish: if the last crab’s parting touch zeroes the spark in the same frame the wave clears, the victory screen asks one question first — is the spark’s health above zero? The touch lands inside the physics step, before the exit is counted, so the read is settled by the time the win arrives. Dead spark, no panel: death wins the tie. You have to be standing to win it.

The victory screen (victory.gd)

extends CanvasLayer
## Victory — Spark Swarm Episode 13 ("You Win").
##
## The mirror of Ep7's GameOver screen, built the same way on
## purpose: a CanvasLayer that hears one signal, fills in the
## numbers, shows its panel and pauses the tree. Where GameOver
## hears the spark's died, Victory hears the spawner's run_won
## (Ep13) — and the stats it shows are the counters the spawner
## kept along the way, so every number on this screen is a number
## the game truly tracked.
##
## Scene setup (built in the episode, mirroring GameOver):
##   Victory (CanvasLayer, this script)
##     Process Mode: Always (set in the Inspector — the same Ep7
##     rule: without it, the paused tree stops this node too and
##     the restart key goes deaf)
##   └── Panel (Control, full rect, starts hidden)
##       ├── Dim (ColorRect, full rect, black, alpha 0.55)
##       ├── Title (Label, "YOU WIN")
##       ├── Waves (Label, "Waves cleared  10")
##       ├── Zapped (Label, "Crabs zapped  130")
##       ├── Gems (Label, "Gems collected  27")
##       ├── Score (Label, "Score  270")
##       └── Hint (Label, "Press R to run it back")
##
## Project setup: the input action "restart" on the R key,
## added in Episode 7.
##
## THE EP13 BUG (first version, kept here as the warning): this
## screen first checked the win by POLLING in _process —
##     if spawner.crabs_remaining() == 0: show_victory()
## crabs_remaining() reads 0 before wave 1 spawns and during every
## break, so the game declared victory on its opening frame. The
## fix is Ep9's rule wearing a new hat: moments are events, never
## polls. The win now arrives as the run_won signal, shouted from
## inside the wave_cleared check — the one moment "the final wave
## is cleared" is actually true.

@onready var _panel: Control = $Panel
@onready var _waves: Label = $Panel/Waves
@onready var _zapped: Label = $Panel/Zapped
@onready var _gems: Label = $Panel/Gems
@onready var _score: Label = $Panel/Score

var _shown: bool = false


func _ready() -> void:
	_panel.hide()
	# The spawner is found by its group — the lookup the Ep5
	# banner and Ep7's GameOver already use for their nodes.
	var spawner := get_tree().get_first_node_in_group("spawner")
	if spawner != null:
		spawner.run_won.connect(_on_run_won)


func _on_run_won(stats: Dictionary) -> void:
	if _shown:
		return
	# THE TIE RULE: if the spark is already dead when the last
	# crab falls, the run is a loss, not a win — you have to be
	# standing to win it. A crab's parting touch sets health to 0
	# inside the physics step, before the exit is processed here,
	# so this read is settled by the time run_won arrives. Ep7's
	# GameOver shows instead.
	var spark := get_tree().get_first_node_in_group("player")
	if spark != null and int(spark.get("health")) <= 0:
		return
	_shown = true
	_waves.text = "Waves cleared  %d" % int(stats["waves_cleared"])
	_zapped.text = "Crabs zapped  %d" % int(stats["crabs_zapped"])
	_gems.text = "Gems collected  %d" % int(stats["gems_collected"])
	_score.text = "Score  %d" % int(stats["score"])
	_panel.show()
	get_tree().paused = true


func _unhandled_input(event: InputEvent) -> void:
	if _shown and event.is_action_pressed("restart"):
		# Unpause FIRST (Ep7's rule): SceneTree.paused survives a
		# scene change, so reloading while paused starts frozen.
		get_tree().paused = false
		get_tree().reload_current_scene()

Run it

  1. Install Godot 4.8 beta 1 (the standard build).
  2. Unzip ep13.zip.
  3. In Godot’s Project Manager, click Import and pick project.godot inside the spark-swarm-ep13 folder.
  4. Press Play (F5). Move with WASD, the arrow keys or a gamepad. Zap with Space or the bottom face button. Clear wave ten — all 130 crabs and the boss — and stand in the gold.

One honest limit: the victory screen is a scoreboard, not a ceremony — no saved best score, no unlocks, and a restart resets everything, by design. And the count is exact: the waves send 4 + 6 + 8 + … + 22 = 130 crabs, so a winning clear zaps 130; gems stay luck (130 kills at one-in-four expect 32.5, so a real run lands 32 or 33, about 325 points).

Make it yours

Change one number and re-run: set final_wave to 3 and you have a practice run — waves of 4, 6 and 8, eighteen crabs — that ends in the same gold panel in about a minute. Then check the counter on the panel: it should read exactly 18. If it does, your books balance.
