Today the run gets an ending: a died signal that fires exactly once, a game over screen that freezes the world and reads the wave you reached, and a restart that actually restarts.

What you build

  1. A died signal and an is_dead state flag on the spark, so death fires exactly once — even when two crabs land on the same physics step. The flag is set before the signal shouts, so listeners already see the final state.
  2. A game over screen on a CanvasLayer: a dim over the frozen arena, GAME OVER, the wave you reached, and the restart hint. The screen finds the spark by its player group and connects to died — the same move the banner used in Episode 5.
  3. The paused-tree trap: pausing the tree stops the game over layer too, so your restart key goes deaf. The fix is one Inspector setting — the layer's Process Mode set to Always.
  4. A restart control: an input action named restart on the R key, added in Project Settings > Input Map — Episode 1's rule: name your controls, then ask for the name in code.
  5. The restart bug: resetting by hand — health back, wave back, panel hidden — never frees the old run's live crabs, and a SpawnTimer still running from the old wave drops an owed crab into the fresh run.
  6. The real fix: unpause first (the paused flag survives a scene change, so reloading while paused starts the new run frozen), then reload_current_scene(). The scene file is the reset list, so the next run starts exactly as saved: health full, wave zero, arena empty.

The ending and the restart (game_over.gd)

func _on_game_over() -> void:
	if _over:
		return
	_over = true
	var wave := 0
	var spawner := get_tree().get_first_node_in_group("spawner")
	if spawner != null:
		wave = int(spawner.get("wave_number"))
	_sub.text = "You reached wave %d" % wave
	_panel.show()
	get_tree().paused = true


func _unhandled_input(event: InputEvent) -> void:
	if _over and event.is_action_pressed("restart"):
		# Unpause FIRST: SceneTree.paused survives a scene change,
		# so reloading while paused starts the new run frozen.
		get_tree().paused = false
		get_tree().reload_current_scene()

What's in the folder

  • game_over.gd: the game over layer — hears died, fills in the wave, pauses the tree, restarts on R (new in this episode)
  • spark.gd: Episodes 1–6, plus the died signal and the is_dead flag (new in this episode)
  • wave_spawner.gd, wave_banner.gd and crab.gd: the Episode 5–6 systems, unchanged
  • arena.tscn: the arena scene, now with the GameOver layer in the tree and the restart action in the project settings

Run it

  1. Install Godot 4.8 beta 1 (the standard build).
  2. Unzip ep07.zip.
  3. In Godot's Project Manager, click Import and pick project.godot inside the spark-swarm-ep07 folder.
  4. Press Play (F5). Move with WASD, the arrow keys or a gamepad. Zap with Space or the bottom face button.

One honest limit: nothing is saved. Your best wave is forgotten the moment you restart, and a restart is a full rebuild of the scene, not a continue. That is fine at this size — and it is exactly what a run-based game wants for now.

Set First Wave Size to 6 and Wave Growth to 3, and predict the run before you play: how many crabs across waves one to three? (27: six, plus nine, plus twelve.) Then chase your own best wave — while you still have to remember it yourself. Episode 8 puts it on the screen.
