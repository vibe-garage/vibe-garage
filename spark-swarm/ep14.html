Thirteen episodes built a game. This one ships it. The difference between a project and a game is a folder: an exported build that runs on a machine with no Godot, no project, no editor — double-click, and the swarm starts. Getting there honestly takes three things: a version that lives where exports can carry it, a preset that says exactly what to build, and the templates every export needs. It also takes surviving the season’s sneakiest bug: a label that read its version from a loose text file, worked perfectly in the editor, and came up empty in the exported game — because exports only pack what’s part of the game. Settings travel. Stray files don’t.

What you build

  1. Give the build a name tag: open Project > Project Settings > Application > Config and set Version to 1.0. A version is just the name tag a build wears, so you always know which copy you’re holding — v0.8, v0.9, v1.0. Settings like this one are packed into every export automatically; that fact runs this whole episode.
  2. Show it in the corner: a Label named VersionLabel in the arena scene, anchored bottom-right, clear of the HUD stack. Its script (below) reads the version from Project Settings at startup and shows it as “v1.0”. It never opens a file. Set the project’s icon the same way — Application > Config > Icon — to the spark’s own sprite, so the exported game wears the game’s face.
  3. Meet the trap first (so you recognise it forever): the label’s first version read a loose version.txt file from the project folder. In the editor it worked — the editor can see every file on disk. The export came up empty: an export only packs the files Godot knows are part of the game — scenes, scripts, textures, the icon, and Project Settings. A stray text file is none of those, so it never made the trip, and the label reached for a file that wasn’t there. Nothing crashed; the corner was just empty.
  4. Answer the templates question honestly: exporting needs Godot’s export templates — the prebuilt runners your game gets wrapped in. They’re a separate download from the editor (Project > Export offers to fetch them), installed once, and then they’re invisible. No templates, no export; that’s the whole catch, and most tutorials skip saying it.
  5. Write the recipe: export_presets.cfg is a text file that lives in the project. The one preset, Windows Desktop, says: export everything (all_resources), land the game at build/SparkSwarm.exe, and keep the .pck as its own file (include_pck off). The export produces exactly two files — the .exe runner and the .pck it carries — and they only work together, in the same folder.

The version label (version_label.gd)

extends Label
## Spark Swarm Ep14: the version label.
##
## Reads the game's version from Project Settings
## (Project > Project Settings > Application > Config > Version)
## and shows it as "v1.0". Project Settings are packed into every
## export, so this label reads the same in the editor and in the
## exported game.
##
## The first version of this label read a loose "version.txt" file
## from res:// instead. That works in the editor, which can see
## every file in the project folder — but an export only packs
## the files Godot knows are part of the game, so in the exported
## build the file was missing and the label came up empty.
## Settings travel; stray files don't.


func _ready() -> void:
	text = version_text()


static func version_text() -> String:
	var version: String = ProjectSettings.get_setting(
		"application/config/version", "1.0")
	return "v" + version

Run it

  1. Install Godot 4.8 beta 1 (the standard build).
  2. Unzip ep14.zip.
  3. In Godot’s Project Manager, click Import and pick project.godot inside the spark-swarm-ep14 folder.
  4. Press Play (F5). Move with WASD, the arrow keys or a gamepad. Zap with Space or the bottom face button. Check the corner: v1.0. Then export it (Project > Export, templates installed) and check the corner again — same label, no editor.

Version 1.0, honestly: no menus — it boots straight into the swarm; silent hits — the sound polish never made the cut; a minimal boss; no saving — close it and the run resets. That’s not a broken game; that’s a finished version one, with a clear list of what grows next. The run itself is the same math as ever: waves of 4 + 6 + 8 + … + 22 = 130 crabs, and even with perfect play the swarm alone needs 144 seconds — two minutes twenty-four — to finish arriving.

Make it yours

Change one thing and re-export: set the version to 1.1 in Project Settings, export again, and check the corner of the new build. If it reads v1.1, your settings made the trip — the whole lesson in one move. Then try the trap on purpose: point the label at a loose file, export, and watch the corner come up empty. Knowing exactly why it’s empty is the difference between a project and a game you understand.
